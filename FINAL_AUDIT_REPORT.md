# CrashGuard — Final Audit Report

**Project:** CrashGuard Android Crash Guard Library (`CrashGuard-1.0.0.zip`)
**Audit date:** 2026-11-07
**Audited version:** 1.0.0 → 1.0.0 (fixed)
**Toolchain used for verification:** JDK 17.0.13 (Temurin), Gradle 8.7, AGP 8.3.2,
Android SDK Platform 34, Build-Tools 34.0.0, Linux x86_64.

---

## 1. Original project problems

The original archive **did not compile**. The demo application referenced a package
that does not exist, and the library module requested an SDK level that the declared
Android Gradle Plugin cannot build. Beyond the hard build failures, several runtime
defects meant that even a successful build would not have produced a working crash guard.

### 1.1 Build-blocking defects

| # | File | Problem |
|---|---|---|
| B1 | `app/src/main/java/.../MainActivity.java` | Imports `com.roni.crashguard.demo.CrashGuard` and `...CrashGuardConfig`. The real package is `com.roni.library.crashguard`. **Compile error.** |
| B2 | `MainActivity.java` | `new CrashGuardConfig.Builder()` — the `Builder` constructor is private. **Compile error.** |
| B3 | `MainActivity.java` | `.debugEnabled(true)` and `.tag("App")` do not exist on the builder. **Compile error.** |
| B4 | `MainActivity.java` | `CrashGuard.getInstance().init(...)` — no `init` method. **Compile error.** |
| B5 | `MainActivity.java` | `CrashGuard.getInstance().isInitialized()` — no such instance method. **Compile error.** |
| B6 | `crash-guard/build.gradle` | `compileSdk 36` / `targetSdk 36` with AGP 8.3.2. AGP 8.3 supports compileSdk 34; 36 requires AGP 8.9+. **Build error.** |
| B7 | `crash-guard/build.gradle` | `androidx.core:core:1.15.0` requires `compileSdk 35`. **Build error** against compileSdk 34. |
| B8 | `app/build.gradle` | `compileSdk 34` consuming an AAR built with `compileSdk 36`. **Variant/compileSdk mismatch.** |
| B9 | `app/src/main/res/values/themes.xml` | `Theme.MaterialComponents.DayNight.DarkActionBar` while the library ships a Material3 crash theme — two different Material theme families in one APK. |
| B10 | `app/build.gradle` | `BuildConfig` is not generated by AGP 8.x unless `buildFeatures { buildConfig true }` is set. |

### 1.2 Crash-guard functionality defects

| # | File | Problem |
|---|---|---|
| F1 | `CrashGuard.java` | The constructor calls the **static** `addBreadcrumb(...)`, but `instance` is still `null` at that point, so the "initialized" breadcrumb was silently dropped. |
| F2 | `CrashHandler.java` | The full `CrashReport` (with stack trace + breadcrumbs) was passed through an `Intent` extra to another process. Long traces exceed the 1 MB Binder limit → `TransactionTooLargeException`, and the crash screen would fail to open. |
| F3 | `CrashHandler.java` | `report.setCustomData(customData)` stored the **live** `ConcurrentHashMap`. Any later `setCustomKey()` mutated an already-persisted report. |
| F4 | `CrashHandler.java` | `defaultHandler` was captured without a self-reference guard. A second `install()` after `uninstall()` could chain the handler to itself → infinite recursion. |
| F5 | `CrashHandler.java` | 150 ms grace period before `Process.killProcess()` is too short on slow devices for the crash activity in `:crash_guard_process` to be created. |
| F6 | `CrashGuard.java` | No `uninstall()` / `release()`. The previous uncaught handler could never be restored, and the README documented a `release()` that did not exist. |
| F7 | `CrashGuard.java` | `logHandledException()` omitted `androidVersion`, `sdkInt`, device model/manufacturer/product, root state and storage figures — handled reports were far less useful than uncaught ones. |
| F8 | `CrashGuard.java` | No `getLatestReport()` / `getStoredReportCount()`; the demo had no way to show report state. |
| F9 | `CrashReportStorage.java` | Reports were written **directly** to the final file. A process killed mid-write left a truncated, unparseable JSON file. |
| F10 | `CrashReportStorage.java` | `Comparator.comparingLong(File::lastModified)` is **API 24+** while `minSdk` is 21 → `NoSuchMethodError` on Android 5.0–6.0 when pruning reports. *(Found by `lintRelease`.)* |
| F11 | `CrashReportStorage.java` | No `getReport(id)` lookup, so the crash activity could not reload a report by id. |
| F12 | `DefaultCrashActivity.java` | Relied solely on the serialisable Intent extra; no disk fallback by id. |
| F13 | `DefaultCrashActivity.java` | `onBackPressed()` override (deprecated) instead of the `OnBackPressedDispatcher`. |
| F14 | `CrashNotificationManager.java` | No `areNotificationsEnabled()` check; on Android 13+ without `POST_NOTIFICATIONS` the notification silently never appeared. |
| F15 | `CrashNotificationManager.java` | No way to cancel the notification after review. |
| F16 | `CrashReport.java` | No distinction between uncaught and handled reports; no `tag`; `getBreadcrumbs()`/`getCustomData()` returned live references. |
| F17 | `CrashGuardConfig.java` | No `tag` support even though the demo and docs used `.tag(...)`. |
| F18 | `crash-guard/proguard-rules.pro` | Contained rules for `com.roni.crashguard.demo.**` — a package that does not exist in the library module. |
| F19 | `crash-guard/consumer-rules.pro` | Missing keeps for `CrashHandler`, `CrashReportStorage`, `BreadcrumbTracker`, `CrashNotificationManager`, `DeviceUtils` and the `Serializable` contract. |
| F20 | `crash-guard/build.gradle` | `appcompat` / `material` declared as `implementation`, although `DefaultCrashActivity extends AppCompatActivity` and the crash theme extends `Theme.Material3.*` — both are part of the public surface. |
| F21 | `crash-guard/build.gradle` | `withJavadocJar()` on an Android library is fragile (Javadoc has no `android.jar` on its classpath) and could fail the release build. |
| F22 | `crash-guard/build.gradle` | No `testOptions.unitTests.returnDefaultValues`; no Robolectric, so storage and install paths were untested. |

## 2. Root causes

| Group | Root cause |
|---|---|
| B1–B5 | The demo app was written against an **imagined API** (`init`, `isInitialized`, `debugEnabled`, `tag`, `com.roni.crashguard.demo.*`) that never matched the library that was actually implemented. The two modules were never compiled together. |
| B6–B8 | SDK levels were edited independently per module (`36` in the library, `34` in the app, `34` in the root `ext`). There was no single source of truth, and `androidx.core:1.15.0` was bumped without bumping AGP. |
| B9–B10 | The demo was scaffolded from an old template and never revisited after the library moved to Material3 / AGP 8. |
| F1 | A static helper was used from inside the constructor, before the singleton field was assigned. |
| F2 | The report was treated as a small Intent payload. It is not: stack traces plus 50 breadcrumbs routinely exceed the Binder transaction limit. |
| F3 | A mutable map was handed to a value object without copying. |
| F4 | The previous handler was captured without considering re-installation. |
| F5 | The grace period was a guess, not derived from the cost of cold-starting a second process. |
| F6–F8 | The public API was never completed; the README documented methods that were never written. |
| F9 | `FileOutputStream` was used without a temp-file + rename protocol. |
| F10 | `Comparator.comparingLong` was used without checking the desugaring/API level. Lint caught it; the original CI never ran lint. |
| F11–F13 | The crash activity was designed around the Intent payload instead of the persistent store. |
| F14 | Notification permission handling for Android 13 was never implemented. |
| F16–F17 | The report model was never extended after the config gained new options. |
| F18–F19 | ProGuard files were copy-pasted from the demo module. |
| F20 | `implementation` vs `api` was chosen without considering the public class hierarchy. |
| G1–G2 | Fallback chains were added to "make CI green" instead of fixing the build — the classic failure-masking anti-pattern. |
| G3–G10 | Workflows were written as a single happy-path script with no permissions model, no artifacts and no version guard. |
| P1–P3 | `gradle.properties` was populated with the demo app's identifiers, and the publication block ignored it entirely. |
| P4 | The README coordinate was invented rather than derived from the publication config. |
| P5–P6 | Scripts referenced modules that do not exist. |
| P8 | Nothing ever consumed the published artifact, so a broken POM would have gone unnoticed. |

## 4. What was fixed

### 4.1 Build system
- Single source of truth for SDK levels in the root `ext` block; both modules read it.
- `compileSdk` / `targetSdk` = **34**, `minSdk` = **21** everywhere.
- `androidx.core` downgraded to **1.13.1** (the newest release compatible with compileSdk 34).
- `android.enableJetifier=false` (nothing needs it) and `android.nonTransitiveRClass=true`.
- `buildFeatures { buildConfig true }` added to the demo module.
- Demo theme migrated to `Theme.Material3.DayNight.NoActionBar` to match the library.
- `appcompat` / `material` promoted to `api` in the library so consumers inherit the
  `AppCompatActivity` and `Theme.Material3.*` symbols the AAR exposes.
- `withJavadocJar()` removed; `withSourcesJar()` retained.
- `testOptions.unitTests.returnDefaultValues` + `includeAndroidResources` enabled.

### 4.2 Crash guard runtime
- **F1** — the constructor now writes the init breadcrumb directly to the tracker.
- **F2** — only `reportId` crosses the process boundary; the crash activity reloads the
  report from disk. The legacy serialisable extra is still accepted for compatibility.
- **F3** — `customData` is snapshotted with `new HashMap<>(...)` before being attached.
- **F4** — `CrashHandler` nulls out a self-referencing previous handler.
- **F5** — grace period raised to 400 ms.
- **F6** — `uninstall()` / `release()` restore the previous handler and clear state.
- **F7** — `logHandledException()` now records the full environment snapshot.
- **F8** — added `getLatestReport()` and `getStoredReportCount()`.
- **F9** — atomic write: `.json.tmp` → `fsync` → `renameTo`, with a delete-and-retry fallback.
- **F10** — replaced `Comparator.comparingLong` with an explicit `Comparator<File>` (API 21 safe).
- **F11** — added `CrashReportStorage.getReport(String)` and `getReportCount()`.
- **F12** — `DefaultCrashActivity` resolves the report by id, then legacy extra, then latest on disk.
- **F13** — migrated to `getOnBackPressedDispatcher()`.
- **F14** — `NotificationManagerCompat.areNotificationsEnabled()` gate + `BigTextStyle`.
- **F15** — added `CrashNotificationManager.cancel(Context)`.
- **F16** — `CrashReport` gained `reportType` (`UNCAUGHT`/`HANDLED`), `tag`, `getSummary()`,
  `toJsonString()`, and defensive copies in `setBreadcrumbs` / `setCustomData`.
- **F17** — `CrashGuardConfig` gained `tag` + `setTag()` and a `setDebugEnabled()` alias.
- **F18/F19** — ProGuard rules rewritten for the real package and the `Serializable` contract.
- **F22** — Robolectric added; storage and install paths are now covered by tests.

### 4.3 Demo application
- `DemoApplication` installs CrashGuard in `onCreate()`, guarded by a main-process check so
  the `:crash_guard_process` does not re-install.
- Six crash scenarios: NPE (main), RuntimeException (background), StackOverflowError,
  IllegalStateException, OutOfMemoryError, and a handled (non-fatal) exception.
- Diagnostics panel: add breadcrumb, set custom keys, open report list, clear reports.
- Live status card: install state, report count, active config, breadcrumb count.
- `CrashReportsActivity` — list with type badges, tap for detail, long-press to delete,
  share-all and clear-all menu actions.
- `CrashReportDetailActivity` — full formatted report with copy/share.
- Android 13+ `POST_NOTIFICATIONS` runtime request.
- Full Bengali UI.

### 4.4 CI/CD
- Three separate workflows: `build.yml`, `test.yml`, `release.yml`.
- **All `||` fallbacks removed** — a failing task now fails the job.
- Explicit `permissions:` (`contents: read` for build/test, `contents: write` +
  `packages: write` for release).
- `gradle/actions/setup-gradle@v4` for dependency caching.
- Artifacts uploaded with `if-no-files-found: error`.
- Release workflow verifies `tag == VERSION_NAME`, runs tests, publishes to Maven Local,
  asserts the AAR/POM/sources exist, publishes to GitHub Packages, then creates the
  GitHub Release with `softprops/action-gh-release@v2` and `fail_on_unmatched_files: true`.
- `concurrency` groups cancel superseded runs.

### 4.5 Publishing
- `gradle.properties` now holds the real coordinates: `GROUP=com.roni.library`,
  `POM_ARTIFACT_ID=crash-guard`, `VERSION_NAME=1.0.0`.
- The publication reads those properties (no hardcoded values).
- Full POM metadata: name, description, url, license, developer, SCM.
- GitHub Packages repository wired conditionally on `GITHUB_REPOSITORY` / `GITHUB_ACTOR` /
  `GITHUB_TOKEN`, so local builds never fail on missing credentials.
- `jitpack.yml` publishes only the library module.
- `scripts/build.sh` and `scripts/publish.sh` rewritten (no phantom `:java-library`).
- `integration-test/` added: a standalone app that consumes
  `com.roni.library:crash-guard:1.0.0` from `mavenLocal()`.

## 6. Library architecture changes

**None of the package names, class names, or public method signatures were renamed or
removed.** The architecture is unchanged:

```
CrashGuard (facade, singleton)
  ├── CrashGuardConfig (immutable + Builder)
  ├── CrashHandler (Thread.UncaughtExceptionHandler)
  ├── CrashReportStorage (atomic JSON files, FIFO retention)
  ├── BreadcrumbTracker (synchronised ring buffer)
  ├── CrashReport / Breadcrumb (models)
  ├── DefaultCrashActivity (:crash_guard_process)
  ├── CrashNotificationManager
  └── DeviceUtils
```

Additive changes only:
- `CrashHandler` gained a 6-argument constructor (the 5-argument one is retained).
- `CrashReport` gained `reportType` / `tag` fields (`serialVersionUID` bumped to `2L`).
- `CrashGuardConfig` gained `tag` and `setDebugEnabled()`.
- `CrashNotificationManager` became `final` with a private constructor (it was a
  stateless utility class; no instance was ever created).

## 11. Known issues and remaining limitations

1. **No on-device runtime verification.** The crash flow (process kill → isolated crash
   activity → restart) was verified by code review and by Robolectric-level tests of the
   storage and install paths, but not on a real device or emulator. The demo app ships
   six crash buttons so this can be validated in minutes on hardware.
2. **JitPack coordinate is inferred.** JitPack's multi-module naming convention is
   `com.github.<owner>.<repo>:<module>:<tag>`. This has not been confirmed against a live
   JitPack build because the repository was not pushed from this environment.
3. **`POST_NOTIFICATIONS` is a host responsibility.** The library declares the permission
   but cannot request it; background-crash notifications are silently skipped if the host
   never asks the user.
4. **`DefaultCrashActivity` runs in a second process.** Any `Application` initialisation
   runs twice (once per process). The demo guards against this with a process-name check;
   consumers should do the same if their `Application` does heavy work.
5. **`CrashReport` is still `Serializable`.** The legacy Intent path is retained for
   source compatibility, but the primary path is id-based and disk-backed.
6. **`minSdk` 21 is preserved.** No API-24+ calls remain (lint-verified), but the library
   has not been exercised on an API 21 device.
7. **`withJavadocJar()` was removed.** Javadoc generation for Android libraries is
   unreliable without a custom `android.jar` classpath; sources are published instead.
8. **Release APK is signed with the debug keystore.** Intentional: the demo is not
   distributed and this keeps `assembleRelease` runnable without secrets.
9. **`androidx.core` is pinned to 1.13.1.** Raising it requires raising `compileSdk` to 35
   and AGP to 8.6+.

## 12. How to use and publish

### Consume

```gradle
// settings.gradle
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven { url 'https://jitpack.io' }
    }
}

// app/build.gradle
dependencies {
    implementation 'com.github.infoadmstudio2020-cyber.crash-guard:crash-guard:1.0.0'
}
```

```java
public class MyApp extends Application {
    @Override public void onCreate() {
        super.onCreate();
        CrashGuard.install(this, CrashGuardConfig.newBuilder()
            .setDebugMode(BuildConfig.DEBUG)
            .setTag("my-app")
            .build());
    }
}
```

### Publish to Maven Local

```bash
./gradlew :crash-guard:publishReleasePublicationToMavenLocal
# -> ~/.m2/repository/com/roni/library/crash-guard/1.0.0/
```

### Publish to JitPack

```bash
# 1. Bump VERSION_NAME in gradle.properties
# 2. Commit and push
git add gradle.properties && git commit -m "Release 1.0.0" && git push
# 3. Tag and push
./scripts/publish.sh --tag
# 4. Open https://jitpack.io/#infoadmstudio2020-cyber/crash-guard and trigger the build
```

### Publish to GitHub Packages

Push a `v*` tag. The `Release` workflow publishes automatically using `GITHUB_TOKEN`.

### Verify a release locally

```bash
./gradlew :crash-guard:assembleRelease :crash-guard:testDebugUnitTest :crash-guard:lintRelease
./gradlew :crash-guard:publishReleasePublicationToMavenLocal
cd integration-test && ../gradlew :app:assembleDebug
```
